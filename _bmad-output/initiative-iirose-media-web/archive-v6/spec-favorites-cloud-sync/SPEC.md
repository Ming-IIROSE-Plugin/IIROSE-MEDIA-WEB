# 收藏云同步规格说明书 (Favorites Cloud Sync Spec)

## Why

**要解决一个具体的痛点。** 现有收藏系统（见 `spec-favorites-system`）纯本地 IndexedDB 持久化，用户在手机上收藏的歌，换到电脑上就没了；换浏览器、清缓存、重装，整库消失。用户已明确需要跨设备同步。

同时存在**一个刚被验证的机会**：插件运行在宿站 `messages.html` 上下文，实测可直读宿站账号标识 `window.uid`，且该标识跨登出/重登稳定不变——意味着不需要任何插件自建账号体系就能拿到一个天然的用户分区键。

约束条件是**零成本、零信任**：后端只能跑在免费额度内，而宿站没有任何可用来校验身份的开放 API，所以 uid 只能当分区键、不能当凭据。方案因此定为「uid 分区 + 端到端加密」：服务端只见密文，用户自持同步口令。

## Capabilities

- **CAP-1 同步身份与密钥解锁**
  - **intent:** 用户以宿站账号身份（`window.uid`）加一个自设的同步口令启用同步，加密密钥完全在本地派生，口令与明文收藏永不出端。
  - **success:** 插件能读到非空 uid 并作为分区键；清空宿站 localStorage 后重新登录，uid 不变（实测：登出→清空→重登，uid 逐字节相同）；服务端对象与请求体中均不含明文收藏内容、明文口令或任何宿站口令派生值。

- **CAP-2 加密快照上传与下载**
  - **intent:** 客户端可把本地收藏整体序列化为加密信封存到云端，并可从云端取回、解密还原为与本地同构的收藏记录。
  - **success:** 在同一浏览器一处上传后，用另一个干净的浏览器配置（同账号 + 同口令）拉取，条目数、复合主键、标题、平台、类型、`createdAt` 与上传端完全一致，且可直接点播。

- **CAP-3 首次启用合并与预览确认**
  - **intent:** 首次启用时把云端与本地按复合主键做并集合并，同键冲突保留 `createdAt` 更早的一条，并在写入前把合并结果交给用户确认。
  - **success:** 用夹具（本地 89 条 / 云端 137 条 / 重叠 74 条）验证：预览显示「云端 137 / 本地 89 / 合并后 152」，确认后两端均为 152 条，且重叠项的 `createdAt` 取更早值。

- **CAP-4 删除传播（墓碑）**
  - **intent:** 删除操作以墓碑形式参与同步与合并，保证一台设备删掉的收藏不会被另一台设备复活。
  - **success:** A 设备删除某条 → 同步；B 设备同步后该条消失，A 设备再次同步不会把它带回；墓碑满 30 天后被物理清理。

- **CAP-5 变更驱动的自动同步与手动同步**
  - **intent:** 收藏增删后自动防抖上传，进入插件时自动拉取，并提供「立即同步」入口；不做后台轮询或长连接，只在插件 UI 打开期间每 5 分钟做一次兜底拉取，并在 UI 打开／标签页重新可见／窗口获得焦点时按 60 秒冷却即时拉取。
  - **success:** 一次会话内连续 5 次增删只产生 1 次写请求（5s 防抖窗口内合并）；全流程抓包无周期性重复请求；单活跃用户日请求量落在个位数到十余次的量级。

- **CAP-6 配额与失败反馈**
  - **intent:** 超出体积上限、触发限流、口令错误、离线等失败场景，一律给出可读且可行动的中文提示，而不是静默失败或静默丢数据。
  - **success:** 快照 >512KB 时提示「云端收藏包已满 512KB，请联系铭」；429 时提示稍后再试且本地数据不受影响；AEAD 解密失败时提示「同步口令不正确」并**拒绝覆盖云端**；离线时提示可稍后重试。

- **CAP-7 云端数据自我管理**
  - **intent:** 用户可查看上次同步时间、清空云端副本、关闭同步（保留本地数据不动）。
  - **success:** 「清空云端」后 GET 返回空快照且本地收藏完好；关闭同步后不再发起任何同步请求；重新开启后可选择再次合并。

## Constraints

- **服务端零知识。** 不得存储、记录、转发明文收藏或同步口令；函数不得把请求体写入 CLS 日志。
- **uid 是分区键，不是凭据。** 宿站 `localStorage.cookie.password`（账号口令 MD5）及任何宿站口令派生值，绝不可用作凭据、密钥或服务端秘密。
- **函数URL 必须使用「开放」鉴权。** CAM 鉴权要求浏览器持有腾讯云密钥，不可接受；因此全部抗滥用逻辑必须在函数内部自建。API 网关触发器已下线，HTTP 入口只能是函数URL。
- **对象键只能由服务端生成**，形如 `sync/{uid[0:2]}/{uid}.json`，uid 需通过十六进制白名单校验；函数不得接受客户端指定的任意键，从而不可能被当作通用文件或图床使用。
- **存储桶必须私有读写、不开公网直链**，函数角色权限仅限 `sync/` 前缀的 `PutObject` / `GetObject` / `HeadObject`（GET 路径每次都先 `HeadObject`，漏掉它会让读取全部 403）。
- **存储桶必须开启版本控制**，作为误覆盖与恶意清空的回滚兜底。
- **不得购买套餐包或资源包。** 所有频率上限必须按「零成本」目标设定，并配置费用与日调用量告警。
- **仅已登录账号可同步。** 没有稳定 uid 的游客态不得上传。
- **客户端请求不得经过 `window.iirosemedia.cors` 代理**——那是为第三方 API 跨域准备的，同步端点是自有的、自带 CORS 头，直连即可。
- **不做后台轮询、不做常驻连接、不做逐条端点。**唯一允许的定时请求是「插件 UI 打开期间的 5 分钟兜底拉取」——聊天站里页面常驻可见，仅靠可见性事件不足以维持最终一致。
- **不引入重型加密依赖**，走 WebCrypto 原生（PBKDF2 + AES-GCM）。
- **PBKDF2 迭代次数以「目标设备解锁 ≤1 秒」为准绳。** 上线前必须在至少一台中低端安卓真机实测；实测超标则下调迭代次数，但**不低于 100000**。信封已自带 `kdf.iter`，调整只影响新写入，不破坏已存在数据——这是刻意的设计冗余。
- **同步口令只存内存。** 不提供「记住同步口令」选项（落 localStorage 会削弱加密保证）；页面刷新即失锁，需重新输入。
- **成本口径：按量计费、无套餐。** 不购买套餐包/资源包，且必须实现「无变化不回传密文」的短路，因为**出网流量是主成本项**，请求次数与资源使用量都是零头。
- **快照体积上限 512KB，本期不设条目数上限。**
- **不提供口令找回**，UI 必须明示「忘记同步口令 = 云端收藏不可恢复」。
- **IndexedDB 必须原地从 version 1 升级到 2**（新增同步字段），不得重建或清空现有数据。
- **同步 UI 必须沿用本仓移动端约定**：44px / 48px 触控目标、`max-[768px]` 断点、`buildSelect2` 跨弹窗 300ms 延迟。
- **落地顺序先本地后云端。** 加密、合并、墓碑、防抖这条链必须先对本地 stub 端点验证通过，再接真实函数与 COS；基础设施不是风险大头，同步语义的正确性才是。

## Non-goals

- 不做逐条增量 API（无 per-record CRUD 端点），v1 只做整包快照。
- 不做实时多端推送（WebSocket / 服务端推送）；不做后台轮询（UI 打开期间的 5 分钟兜底拉取不在此列）。
- 不做口令找回、邮箱绑定、插件自建账号体系。
- 不做服务端搜索、统计、推荐、分享或任何需要读明文的云端能力。
- 不做封面或音视频二进制的同步，只同步元数据（封面仍走 URL）。
- 不做从网易云 / B站 官方收藏夹的导入导出。
- 不做多用户共享收藏夹或房间级收藏池。

## Success signal

- 用户在手机上收藏一首歌，在电脑上打开插件（同一 iirose 账号 + 同一同步口令）即可看到该收藏并直接点播；手机端删除后，电脑端下次同步不再出现；整个过程中云端对象对服务端始终不可读。

## Assumptions

- 假定 `window.uid` 在 `messages.html` 上下文长期可读，能扛住宿站前端迭代（用户已确认；实测：可在该上下文直接读取，且账号级稳定）。
- 假定单用户收藏规模在数千条以内，512KB 信封足够（用户已确认；按条目平均约 150–300B 密文估算；若真超限则走 CAP-6 提示）。
- 假定维护者已开通 COS 且桶与函数同地域：桶 `iirose-media-sync-1309510434`、地域 `ap-guangzhou`（见 `docs/deployment/tencent-cloud-functions.md`）；版本控制、生命周期与最小权限角色按该文档与 `backend-architecture.md` 第 7 节清单在控制台开启。
- 假定用户使用强度不构成滥用，因而频率上限设置宽松、以提示代替硬拦截。
- 假定腾讯云账号已过 SCF 三个月免费期，因此**按量计费而非零成本**；目标上限为「每月几元以内」，出网流量是主成本项。
