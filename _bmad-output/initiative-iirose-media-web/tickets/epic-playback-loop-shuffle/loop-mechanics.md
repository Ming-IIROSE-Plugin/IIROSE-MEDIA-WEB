# 单曲循环机制（loop-mechanics）

## 状态机

```
熄灭 --点击(可用)--> 点亮待命
点亮待命 --本人点播的新曲目开始--> 监控中
监控中 --剩余<=阈值--> 执行循环动作
执行循环动作 --成功--> 监控中（同一曲目，新一轮）
执行循环动作 --失败--> 熄灭 + 提示一次
任意状态 --点击/互斥/换房/断线/媒体消失--> 熄灭
```

## 触发阈值

- 基准剩余 5 秒；同时受时长约束：`阈值 = min(5, max(1, duration * 0.25))` 秒，避免短音频（铃声、试听）每几秒回跳。
- 判定条件（全部满足才动作）：播放中、`duration > 0`、`current` 与 `duration` 均为有限值、`duration - current <= 阈值`、`current > 阈值`（防止刚回退到 0 又立刻被判定命中）。
- 每次「播放实例 + 曲目」只触发一次：用 `HostMediaBridge.read().instance` 与曲目标题组成键，动作后写标记；进度回退且随后单调前进超过阈值才清除标记。
- 判定频率沿用 `HostMediaBridge` 的 250ms 快照订阅；禁止用本地 `setInterval` 累加时间。

## 路径 A：静默快退（有媒体管理权限）

- 条件：`controlMode === "silent"`（即 `mediaPermission` 判定为 allowed）。
- 动作：发送 `!15["<","{floor(current)}s"]` 一次，使进度回到 0。
- 不使用 `!16` 绝对定位（协议参数仍未验证）；大秒数回退已实机确认被宿站接受，长曲一次回退即可，不需要多次步进补偿。
- 失败判定：发送后 2 秒内 `current` 未回落到阈值以下，视为未生效，转路径 B（若可用）或熄灭提示。

## 路径 B：预发重播（无媒体管理权限，或路径 A 未生效）

- 前提：宿站自然结束会自动续播下一首，因此**不能等结束**再动作；路径 B 在结束前主动接管。
- 条件：插件持有该曲目的播放报文（`&1{...}`，插件自身通过 `Socket.send` 发送过），且报文记录的曲目标题与当前 `#shareMediaSongName` 一致、房间未变。
- 触发：`0 < duration - current <= 2` 秒时发送一次——用末尾最多 2 秒的截断换取无空档，且抢在宿站自动续播之前。
- 动作：只发送缓存报文一次，**不发卡片**（`SPEC-auto-playback-no-card` CAP-1：循环是无人值守的重复动作，连发卡片会被当作刷平台活跃度）。
- 校验：发送后 25 秒内宿站回读同一曲目标题且 `current` 小于时长的一半（从 0 重新前进），视为成功；否则视为失败（报文被拒、房间已切走、流地址失效），熄灭并提示一次，不再重试。
- 兜底（迟发）：若因节流错过 2 秒窗口且宿站已完成自动续播——仅在当前曲目仍判定为本人时补发一次；已被他人曲目接管则直接熄灭，不抢占。
- 不使用 `moveinputDo`：owner 模式（本人点播但无管理权限）下的自动快退会在公屏留下「快退 N 秒」消息，循环场景等同每曲刷屏，禁止。

## 重播靠队列（真机结论）

- 无静默权限时，提前发出的「卡片 + `&1`」会进入宿站的**点播队列**；歌自然播完后队列推进，同一首重新开始（实测 `cur 279 → 30`、`playing=true`）。**去掉卡片后同样有效**：只发 `&1` 也能让宿站重新起播（维护者 2026-11 真机确认，见 `SPEC-auto-playback-no-card`）。
- **手动把进度拖到结尾不会循环**：本机定位不广播，服务端不知道歌结束，队列不推进；无权限时按钮就以这句话作为提示文案。
- 因此校验窗口放宽到 25 秒：队列接上可能延迟到 20 秒左右，10 秒会在歌已经重新开始时误判失败并熄灯（2026-11 真机复现）。

## 本地兜底（无权限、无缓存）

- 本人点播但报文缓存丢失（典型：刷新页面）时，循环仍然可用：在窗口内调用宿站本地定位 `Utils.service.seekDemandMedia(0)` 把本端进度拉回开头。
- 这条**不广播**（`socket.send` 不发任何报文），房间其他听众不会跟随；因此它只作为「不让按钮变灰」的兜底，优先顺序仍是：静默 `!15` → 缓存重播 → 本地 seek。
- 本地 seek 同样走「回到开头即重新武装」的校验，避免同一轮重复触发。

## 报文缓存的边界

- 只在插件成功调用 `Socket.send` 发出 `&1` 报文时记录：曲目标题、时长、房间标识（`roomnFull`）、原始报文、记录时间。
- 每个房间只保留最近一条；换房或房间标识变化即失效。刷新页面后缓存为空，重播路径在本次会话首次本人点播前不可用。
- 缓存命中要求标题一致：宿站同名不同曲无法区分，此时以「同标题视为同一首」放行，并在实现记录中标注该近似。

## 交互与边界

- 用户手动点新歌：循环目标更新为新歌（若由插件点播则缓存同步更新）。
- 用户手动拖动进度条或点「播放进度」浮窗的定位按钮：不改变循环状态，但动作后 2 秒内暂停触发，避免与手动定位打架。
- 曲目时长 `<= 阈值 * 3`：仍循环，但同一曲目在 30 秒内最多触发 2 次，超出则熄灭并提示「曲目过短，已停止循环」。
- 曲目被他人接管：循环暂停待命，不打断；本人重新点播后恢复（见 ownership-and-lifecycle.md）。
- 关闭循环：立即停止判定与任何待发动作，不做收尾补偿。
