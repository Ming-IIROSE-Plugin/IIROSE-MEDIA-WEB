# 侧栏单曲循环与收藏随机播放

## Description

痛点是「重复听一首」与「连续听自己的收藏」在宿站里都要手动重播：一首歌结束就没有了下文，想要循环得自己盯着进度条、手动点回同一首；想让自己的收藏连续播，只能一条条点。插件已有媒体快照与控制通道（`HostMediaBridge`）、侧栏注入（`SidebarMediaEntry`）与收藏库（`FavoritesStorageService`），足以在没有宿站原生能力的前提下把这两件事自动化。侧栏点亮式开关让「单曲循环」和「收藏随机」各自常驻，且严格只对本人点播的曲目生效。第二轮补上随机的范围控制：原先单曲与整个歌单各算一份、抽取范围是全部收藏，用户无法决定「从哪些歌里随机」，也无法让歌单里的每首歌与单曲同权。

## Outcome

在真实站点桌面与移动视口：开启单曲循环后一首歌播到剩余 5 秒时无缝回到开头继续播（无权限时在结束前续上同一首）并只有一个按钮点亮；点随机弹出面板，勾选两首单曲加某歌单里的三首后确认，连续自动播放的曲目全部落在这五首内、无公屏消息污染，刷新后再开面板仍是这五首；切到「按歌曲」后整单 100 首的歌单明显占多数。他人点播期间两者零动作并保持待命；换房、断线、刷新后按钮回到熄灭且不产生任何自动发送。

## Requirements

1. R1 (CAP-1): 用户在侧栏开关单曲循环与收藏随机，并一眼看出当前开关状态与不可用原因。 — 成功标准:IIROSE-MEDIA-WEB 分组内出现一行两个点亮式按钮；循环一点即亮，随机点击先弹选择面板、确认后才亮（CAP-8）；点亮后视觉状态明确可辨，熄灭即停止后续自动动作；不可用时按钮灰化且点击给出具体原因；宿站重绘侧栏后按钮行自动恢复且不重复。
2. R2 (CAP-2): 用户开启单曲循环后，有媒体管理权限时同一首曲目在当前播放中无缝从头继续。 — 成功标准:剩余 5 秒（且不超过时长 25%）时进度回到 0 且播放不中断、无公屏消息、无新增点播卡片；同一播放实例只触发一次；回到开头后进度单调前进，不会在末尾反复触发。
3. R3 (CAP-3): 没有媒体管理权限时，用户开启单曲循环仍能在曲目结束后接着重新播放同一首。 — 成功标准:宿站自动续播发生前重新发起同一首，宿站回读显示同一曲目重新播放且进度从 0 前进；重播失败（重播数据缺失、25 秒无回读、已切到他曲）时停止循环、熄灭按钮并提示一次原因，不进入重试风暴，也不干扰他人曲目。
4. R4 (CAP-4): 用户开启收藏随机后，系统只在用户选定的范围内随机续播下一首，无需干预。 — 成功标准:剩余 20 秒开始解析候选、剩余 5 秒发送，曲目结束后播放的是选定范围内的另一首，范围外的收藏与歌单曲目从不出现；同一轮内不重复已播歌曲、不立即重复当前曲目；无版权/解析失败自动改抽（上限 5 首），全部失败提示一次并熄灭；自动起播只发播放报文、永不发点播卡片（见 `SPEC-auto-playback-no-card`）。
5. R5 (CAP-5): 两个开关只作用于本人点播的曲目，别人点播时不插手，本人重新点播后继续生效。 — 成功标准:当前曲目点播者不是本人（含点播者信息未知）时零动作、零发送，开关保持原状态待命；本人再次点播的曲目立即重新纳入循环/随机判定；点播者中途被他人接管时不打断对方、不排队插播。
6. R6 (CAP-6): 用户随时可切换或关闭自动播放，并且状态不会在异常场景下失控。 — 成功标准:两个开关互斥（点亮其一自动熄灭另一）；关闭后不再有任何自动发送；换房、断线、连接恢复、媒体消失、插件被卸载时自动动作立即停止且按钮回到不可用/熄灭；刷新页面后全部默认熄灭。
7. R7 (CAP-8): 用户点亮收藏随机前，在插件自有面板中选定随机范围：单曲/视频、整个歌单或专辑，或展开歌单/专辑只勾其中若干首。 — 成功标准:熄灭态点随机弹出面板，列出所选平台标签（CAP-11）的全部收藏；整条勾选、展开后部分勾选、按标题/作者搜索过滤、全选/全不选（作用于当前可见行）均可用，歌单行显示全选/部分/未选三态；未选任何内容时「开始随机」不可点；确认后面板关闭且随机点亮，取消（关闭按钮、取消、Esc、系统返回）后随机保持熄灭、循环状态不变；点亮态点按即熄灭，再次点击重新弹面板；桌面与移动视口都可完成选择且无裁切。
8. R8 (CAP-9): 用户决定随机的权重：按收藏条目平等，或按歌曲平等。 — 成功标准:面板内有两态开关；「按条目」时每个选中条目（单曲或整个/部分歌单）被抽中概率相同；「按歌曲」时每首被选中的歌概率相同（含 100 首的整单 = 100 份）；切换在下一次抽取即生效并与选择一起持久化。
9. R9 (CAP-10): 用户下次打开面板时看到上次确认的选择，不必重选。 — 成功标准:确认后的选择、权重与随机平台按账号保存在本机（选择与权重按平台分开），刷新页面、重进房间后再次打开面板预填上次选择；首次（无记录）默认全部收藏整条勾选；上次确认后新增的收藏不自动纳入、面板中默认未勾选；已删除的收藏与已不在歌单内的曲目静默剔除；不写入云同步数据。
10. R10 (CAP-11): 用户在选择面板内切换随机所用的平台（网易云 / B站），不受主插件页面焦点影响。 — 成功标准:面板顶部有两个平台标签，切换即显示该平台收藏并保留各标签本次未保存的勾选；确认后以当前标签平台点亮随机，并保存所有本次改动过的平台选择；点亮期间主插件切换页面不熄灭、不改平台；只列有收藏功能的平台（网易云、B站）；没有收藏的平台标签显示空态且不可确认；首次打开停在设置「插件启动默认页面」对应的平台（音乐→网易云、视频→B站、其他→网易云），之后停在上次确认的平台。
11. R11 (CAP-12): 有收藏功能的平台变多时，面板的平台标签依然好点、不拥挤。 — 成功标准:只显示有收藏的平台（另加已存随机平台）；只有一个平台时不显示标签行；1～3 个为等宽分段；4 个及以上为可横向滑动的胶囊标签，每个触控高度 ≥44px、右缘渐隐提示更多、选中项自动滚入视野；左右键与 Home/End 可切换；圆角按首尾自动处理。
12. R12 (CAP-13): 用户可以把选择面板拖到任意位置，下次打开（包括刷新页面后）仍出现在那里。 — 成功标准:按住面板头部拖动即移动，松手后位置保存在本机；刷新或重新打开面板出现在保存的位置；任何视口下面板都不超出可见区（四边留 12px），窗口变小或手机旋转后自动收回视口内；拖动不触发头部按钮，也不影响列表滚动；无保存位置时保持原默认摆放。
13. R13 (CAP-14): 选择面板打开期间，用户仍能照常使用聊天室（回复消息、点宿站按钮、滚动聊天），点面板外不会关闭面板。 — 成功标准:面板外无遮罩，点击、输入、滚动都由宿站正常处理且面板保持打开；关闭只经 ✕、取消、确认、Esc（焦点在面板内）或系统返回；手机首次打开（无已存位置）面板不挡住底部聊天输入栏；面板内操作不影响宿站。

## Constraints

- 复用现有模块与通道：媒体快照与控制走 `HostMediaBridge`，侧栏注入走 `SidebarMediaEntry`，收藏读取走 `FavoritesStorageService` 与 `restorePlatformData`，点播走各平台既有 `MOD/VOD` 入口，歌单/专辑曲目走既有 `getSongListDetail`/`getAlbumDetail`；不引入新依赖。
- 网易云请求（含面板展开歌单）一律经 `SendFetch.neteaseRequest`，不得自拼 CORS 前缀；展开详情按需懒加载、会话内缓存，加载失败只影响该行并可重试。
- 静默快退只走已验证的 `!15["<","Ns"]` 白名单命令；重播只走「再次发送插件发出的 `&1` 播放报文」，不得伪造聊天消息，不得调用 `moveinputDo` 自动发公屏指令。
- 自动动作零聊天：循环重播与随机起播永不发点播卡片（`SPEC-auto-playback-no-card`），其余入口按播报档位发送媒体卡片；除此之外不向公屏发送任何消息；不覆盖聊天草稿与选区。
- 触发判定只用宿站时间字段（`shareMediaCurrentTime` / `shareMediaDuration` / 播放状态 / 点播者 DOM）差值，不使用本地计时累加；后台标签节流下行为不变。
- 时长未知或时长为 0（直播、电台、未就绪）不参与循环与随机；暂停状态不触发。
- 宿站曲目自然结束后会自动续播下一首，所有自动动作必须在结束前发起或在结束态立即接管，不得抢占他人曲目。
- 自动动作发起后若宿站已切到他曲，不得再补发、不得抢占他人曲目，只按失败处理。
- 侧栏按钮行与选择面板都必须幂等：宿站重绘、折叠展开、换房、重复注入后不产生重复节点；卸载时清理全部注入节点与监听。
- 选择面板是插件自有 Preact 组件，不使用宿站 `buildSelect2`；样式写 Tailwind 类，不新增 SCSS。
- 图标自包含（SVG 或 `#id::before` + `font-family:"md"`），禁止借用宿站 `mdi-*` 类；移动端触控目标不小于 44×44，断点沿用 `max-[768px]`；封面先 `http→https` 升级并挂 `onerror` 回退。
- 单个页面只允许一个自动播放控制器：重复注入或同页多实例时不得产生两次触发（见 ownership-and-lifecycle.md）。
- 五份 companion 是完整验收契约的一部分；宿站行为以已确认事实为准（自然结束会自动续播且进度停在末尾、`!15` 接受大秒数快退、流地址有效期很长），未验证项须在实现记录中单列。

## Boundaries

- 不做播放队列、顺序播放、列表循环、多曲循环、历史记录或推荐。
- 不做跨平台混播：一次点亮只在面板选定的一个平台内随机。
- 不做随机选择的云同步与跨设备共享（本轮只存本机，云同步留待后续轮次）。
- 不在面板里展开 B 站多分 P 视频，视频只能整条勾选。
- 不在面板里增删收藏、改歌单内容或排序。
- 不做刷新页面后的开关恢复（选择会记住，点亮状态不会）。
- 不做音量、暂停、倍速、上/下一曲的手动控制，不替代「播放进度」浮窗。
- 不做自定义触发阈值，也不做两种权重模式之外的权重规则。
- 不保证对非插件来源点播的曲目（宿站原生面板点播）也能循环。

## Notes

- Assumption: 宿站移动端侧栏同样渲染 IIROSE-MEDIA-WEB 分组与新按钮行（`SidebarMediaEntry` 现有适配未区分视口）。
- Assumption: 之后打开面板默认显示上次确认的平台（首次规则见 CAP-11，已向用户说明）。
- Assumption: 循环的重播报文只对插件自己发起的点播可用；宿站原生面板点播的曲目在无媒体权限时视为不可循环，按钮说明该原因。
