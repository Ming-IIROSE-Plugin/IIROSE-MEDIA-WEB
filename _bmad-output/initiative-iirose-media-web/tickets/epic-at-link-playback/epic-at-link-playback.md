# 输入框 @ 链接自动解析播放与私聊防泄露增强

## Description

要解决的痛点与体验断层：用户习惯在聊天输入框以 `@链接` 或 `@歌名` 的直觉方式快速点播或搜索媒体。但当前实现存在三大严重缺陷：其一，由于代理钩子为 `async` 异步函数，在私聊界面下破坏了宿站判断拦截的同步布尔值契约，导致用户输入的 `@链接` 或 `@歌名` 被直接当作私聊消息外发，泄露用户输入；其二，对网易云和 B 站链接解析极其严苛脆弱，不支持移动端短链（`163cn.tv`、`b23.tv`）、带中文修饰语的分享文案、路径 ID 及分 P 选集点播；其三，缺乏直链媒体（带或不带 `.mp3`/`.mp4` 等扩展名）的智能嗅探与无感知优雅放行机制。本次演进旨在彻底杜绝私聊外发泄露，并全面完善链接自动解析与多选点播体验。

## Outcome

1. 在宿站私聊面板中输入 `@https://b23.tv/wHdK6aI`、`@https://163cn.tv/bit1nU3J` 及 `@晴天`，私聊记录不产生任何新消息，房间内媒体正常播放或插件面板展开并载入搜索； 2. 在房间输入框中测试网易云/B站长短链及 APP 分享文案，单曲与单 P 视频直接点播，歌单/专辑及多 P 视频弹出正序/乱序/选集多选对话框，完成选集后二次确认顺序并成功播放所选子集； 3. 输入有效直链媒体成功播放；探测超过 8 秒弹出“直链媒体探测超时”提示；输入未知 URL 放行宿站原生逻辑； 4. 设置中关闭“代理蔷薇@输入”后，输入框恢复宿站原生行为； 5. `npm run build` 成功完成单文件构建且无类型错误。

## Requirements

1. R1 (CAP-1): 用户无论在公屏房间还是私聊面板中输入以 `@` 触发的指令（链接点播或媒体搜索），插件均能拦截该行为并阻止该文本作为聊天消息发出。 — 成功标准:在私聊面板中输入 `@` 链接或 `@` 关键词并回车，私聊对象收不到任何该文本消息，输入框正常清空，插件在房间中触发对应点播或搜索流程；公屏下输入同样不作为消息发出。
2. R2 (CAP-2): 用户在输入框以 `@` 输入网易云音乐单曲、专辑、歌单的长链、短链或客户端分享文本（无论是否附带中文标题、说明文案及杂项 query 参数），插件均能识别对应资源类型与 ID 并发起点播；对专辑与歌单支持正序、乱序及多选选集播放。 — 成功标准:对单曲长链（`/#/song?id=`、`/song?id=`）、短链（`163cn.tv/...`）、APP分享文案直接解析点播；对专辑与歌单（长链、短链、APP分享文案），弹出「正序点播 / 乱序点播 / 选集点播」选项；若选择「选集点播」，唤起包含所有曲目的多选对话框，用户勾选并点击完成后，二次确认正序或乱序播放并执行点播。
3. R3 (CAP-3): 用户在输入框以 `@` 输入 B 站视频长链（含无协议前缀）、`b23.tv` 短链或客户端分享文本时，插件解析出对应 BVID 并点播；对多 P 视频支持根据链接参数直接播放指定分 P，或弹出正序/乱序/选集多选对话框。 — 成功标准:能够正确解析长链（含缺省 `https://` 的 `bilibili.com/video/BV...`）、短链（`https://b23.tv/...`）及带中文标题与话题的分享文案；若 URL 携带 `?p=N`，直接播放第 N P；若未指定 P 且视频为多分 P，弹出「正序点播 / 乱序点播 / 选集点播」对话框，选集模式下支持勾选多个分 P 并在确认正序/乱序后播放所选分 P；单集视频直接点播。
4. R4 (CAP-4): 用户在输入框以 `@` 输入音视频媒体直链（含常见扩展名或无扩展名）时，插件尝试嗅探媒体属性并创建媒体卡片点播（无封面或作者时使用默认占位）；若探测超时或非媒体链接，弹出提示或放行至宿站原生逻辑处理。 — 成功标准:对显式扩展名直链，提取文件名占位标题、歌手设为“直链播放”、使用默认封面并探测时长后发送媒体卡片；对无扩展名直链发起 HEAD 探测，`audio/*` 或 `video/*` 正常点播；若探测耗时超过 8 秒，弹出“直链媒体探测超时”提示；若明确为非媒体链接，原样放行至宿站原生 `moveinputDo` 执行原生逻辑，无异常抛出。
5. R5 (CAP-5): 用户在输入框输入 `@歌曲名称`（非 URL 文本且非原生快捷指令）时，插件呼出媒体窗口并将关键词填入搜索框触发检索，且在私聊与公屏下均不发送该文本。 — 成功标准:输入 `@周杰伦 晴天` 回车，媒体容器展开并显示搜索关键词与对应结果，当前聊天框无任何聊天消息发出。

## Constraints

- **同步返回值契约约束**：宿站 `moveinputDo(this.value, 1)` 在私聊（`pmFull`）下依赖同步返回值的 falsy/truthy 判断是否调用 `msgfetch` 外发；插件拦截函数在命中 `@` 时**必须同步返回 `false`**，严禁返回 Promise；所有异步网络请求（重定向追踪、元数据探测、点播发包）必须以解耦的异步任务在后台执行。
- **设置开关还原保证**：必须严格遵循插件设置中的“代理蔷薇@输入”（`chatBox.isProxyAtInput`）开关状态；当该设置关闭时，必须还原回备份的原始 `moveinputDo` 方法，不执行任何拦截与代理。
- **短链重定向必须走 CORS 代理**：`b23.tv` 与 `163cn.tv` 等第三方短链无跨域头，重定向探测必须通过 CORS 代理（如 Tencent SCF 代理），通过 302 响应头 `Location` 或 HTML 跳转目标提取长链，严禁在宿站域直接请求无 CORS 响应的短链。
- **URL 提取健壮性**：严禁直接对用户输入执行 `new URL(e.slice(1))`，必须先使用正则表达式从分享文案中提取目标 URL 实体，并自动补全缺少协议前缀的链接（如将 `bilibili.com/...` 补齐为 `https://bilibili.com/...`）。
- **原生逻辑透传保全**：未命中插件能力的输入（如宿站原生快捷键 `@!`, `@@#`, `@$`, 纯聊天文本等），必须原样透传参数 `(e, t)` 调用备份的原始 `moveinputDo`，不得破坏宿站原生体系。
- **零新依赖与工程纯度**：遵循项目规范，不引入额外 npm 包，保持 Vite 单文件 UMD 构建纯度，`npm run build` 必须无类型报错通过。

## Boundaries

- 不支持除网易云音乐外的第三方音乐平台（如 QQ 音乐、酷狗等）分享短链解析（由后续专项支持）。
- 不支持私聊窗口内单人专属私密播放器（IIROSE 媒体系统本质为房间广播媒体流，点播行为始终作用于当前所在房间）。
- 不自建独立后端媒体抓取爬虫服务，直链媒体仅通过浏览器客户端能力与现有代理完成探测。
