# 加密与密钥规格 (crypto-spec.md)

SPEC.md 中 CAP-1 / CAP-2 / CAP-6 以及全部零知识约束的技术落地。全部使用 **WebCrypto 原生 API**，不引入任何加密依赖。

## 1. 密钥派生与两级密钥

```
口令 ──PBKDF2-SHA256(salt, 310000)──► KEK（32B，仅用于包裹/解包 DEK）
DEK  ── 32B 随机字节 ──────────────► 用 AES-GCM-256 加密快照
```

- **DEK（数据加密密钥）**：首次启用时 `crypto.getRandomValues(new Uint8Array(32))` 生成，之后不再变。
- **KEK（密钥加密密钥）**：`PBKDF2-SHA256(passphrase, salt, 310000, 32字节)`，只用来包裹 DEK。
  - 迭代次数 310000 为 OWASP 量级取值。**桌面实测 43ms；低端安卓尚未实测**——CDP 的 CPU 降频对 `crypto.subtle` 无效（1×–12× 均 43–45ms，原生 KDF 不跑在被降频的主线程上），故低端机数字为外推（约 215–860ms），待真机补测。
- 包裹只在**生成 DEK 时做一次**：`wrapped.ct = AES-GCM(KEK, wrapped.iv, DEK, AAD = uid|v|"dek")`，之后该 `wrapped` 块随信封**原样复用**。
  - 这不算 IV 复用：同一 KEK、同一 IV、同一明文（DEK 恒定）⇒ 密文恒定，不存在「同 key 同 IV 加密不同明文」的 GCM 失效条件。
  - **只有 DEK 本身变化时**（轮换密钥）才重新包裹，且必须使用**新的 IV**。快照自身的 `iv` 仍是每次写入都重新生成。
- 使用：把 DEK 原始字节 `importKey("raw", …, "AES-GCM", extractable=false, ["encrypt","decrypt"])`，**以不可导出句柄的形式参与实际加解密**。
- 选 PBKDF2 而非 Argon2id：后者需要 WASM 载荷，与「不新增重型加密依赖」及包体约束冲突。此为有意识的取舍，非疏漏。

### 1.1 本机密钥缓存（免重复输入口令）

- 首次启用或首次解锁后，把 **DEK 的不可导出 `CryptoKey` 句柄**按 uid 存进 IndexedDB（结构化克隆）。原始字节取不出来，句柄只在同一浏览器 profile 内可用。
- 之后每次进入插件可直接从缓存解锁，**无需再次输入口令**；口令退化为「首次启用」与「换设备」的凭证。
- 缓存**按 uid 隔离**；uid 不匹配即视为无缓存。
- 设置面板必须提供「忘记本机密钥」：删除缓存句柄，回到需要输口令的状态。
- **威胁模型的边界如实说明**：缓存不削弱对「服务端/云端」的保护——密钥从不离开设备；它只把「设备被他人拿到」这一类风险从「需要口令」降为「本地已有明文收藏」这同一级别。

## 2. 载荷加密

```
iv  = crypto.getRandomValues(new Uint8Array(12))   // 每次写入都重新生成，绝不复用
aad = new TextEncoder().encode(`${uid}|${v}|${updatedAt}`)
ct  = AES-GCM-Encrypt(DEK, iv, UTF8(JSON.stringify(snapshot)), { additionalData: aad })
```

- **AAD 绑定 `uid|v|updatedAt`**：防止服务端或第三方把某个用户的密文挪到另一个 uid 的键下复用，也防止旧快照被改 `updatedAt` 后当作新快照重放。
- GCM tag 长度 128 位（默认），随 `ct` 一并 base64 编码。
- 解密时 AAD 必须用**本地重算**的 `uid|v|updatedAt`（`updatedAt` 取信封字段值），不得信任其他来源。

## 3. 明文快照的敏感度

快照内含：收藏条目的平台、类型、原始 ID、标题、作者、封面 URL、`createdAt`、以及完整 `platformData`。这是用户的兴趣画像，属于个人数据。

- 客户端负责在**任何** UI 与日志中不打印明文快照。
- 服务端不解密、不解析 `ct`。
- 封面 URL 保留为纯 URL（不同步二进制）；注意部分封面为 `http://`，本地渲染前仍按既有约定升级为 `https://`。

## 4. 失败语义

| 现象 | 判定 | 行为 |
|---|---|---|
| `decrypt()` 抛错 | 口令错误 **或** 密文被篡改 **或** 被挪到别的 uid 下 | CAP-6 提示「同步口令不正确」；**禁止 PUT**，绝不覆盖云端以免把可解密的历史数据冲掉 |
| 信封字段缺失/版本未知 | 服务端或半成品写入 | 视为不可用，提示后停下 |
| 用户主动「重置口令」 | 显式操作 | 用新口令重新加密当前本地全量并覆盖云端；必须先二次确认，且提示旧口令加密的云端副本将被覆盖（COS 版本控制仍可回滚） |

## 5. 威胁模型

| 威胁 | 是否被覆盖 | 机制 |
|---|---|---|
| 服务端（或其运维）读取收藏内容 | ✅ | 零知识：只有密文，口令从不传输 |
| 服务端泄露对象文件 | ✅ | 同上；泄露只得到密文 |
| 他人用已知 uid 读取你的收藏 | ✅ | 只能拿到密文，无口令无法解密 |
| 他人用已知 uid **覆盖/清空**你的对象 | ⚠️ 部分 | 覆盖后解不开，客户端 AEAD 校验失败会拒绝使用；清空靠 COS 版本控制回滚。**uid 是半公开标识，无法从协议层杜绝此类骚扰，只能靠版本控制兜底** |
| 浏览器扩展 / 恶意脚本读取本地明文 | ❌ 不在范围内 | 本地 IndexedDB 明文是既有设计，端到端加密只保护「在途与云端」 |
| 宿站账号被盗，攻击者装上插件 | ❌ 不在范围内 | 仍需同步口令才能解密 |

## 6. 明确禁止

- **禁止**使用宿站 `localStorage.cookie.password`（账号口令 MD5）或任何宿站口令派生值作为口令、密钥、盐或服务端校验依据。它同源可读，但一旦上传即等同泄露账号凭据。
- **禁止**把口令写入 localStorage、sessionStorage、日志、URL 或任何请求头。
- **禁止**缓存 DEK 的原始字节或任何可导出的密钥材料：本机缓存**只允许**存 `extractable: false` 的 `CryptoKey` 句柄。
- **禁止**复用 IV（快照与包裹 DEK 各自每次写入都换新 IV）。
- **禁止**在服务端实现任何形式的「口令校验」端点——那会创造一个可离线爆破的校验器。
