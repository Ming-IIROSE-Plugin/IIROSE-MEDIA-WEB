# 主面板窗口模式

## Description

要解决的痛点：主面板打开时占满页面，聊天区被移出屏幕，页面点击也被拦截，桌面用户没法边聊天边点歌。窗口模式让面板变成可拖动、可缩放的窗口，且位置刷新后不丢；不想要的用户继续用原版全屏，所以默认仍是全屏。

## Requirements

Verify: - 在 iirose.com 真实房间的桌面视口打开设置开关，把窗口拖到角落并缩到最小，界面不挤坏；一边在聊天框发消息，一边在窗口里搜索并点播一首歌；刷新后窗口回到原位和原大小。把设置关掉后，面板与现版本的全屏表现一致。

Criteria (摘自 v6 SPEC 的 Capabilities):

1. **CAP-1** 用户可以在设置里选择主面板用全屏（原版）还是窗口模式。 — 成功标准:全新安装和没有这一项的旧存档都是全屏，行为与现版本一致；打开开关后面板立即变成窗口，关闭后立即回到全屏，无需刷新；选择在刷新后保留；写盘失败时提示「设置保存失败，请重试」。
2. **CAP-2** 用户可以拖动标题栏移动窗口，也可以用标题栏上的按钮关闭窗口。 — 成功标准:约 32px 的标题栏只在窗口模式出现；窗口跟手移动，无跳动，也无法拖出视口；从关闭钮按下不会开始拖动，点击后窗口关闭；关闭再打开时窗口停在原位，模式、关键词和页码不变。
3. **CAP-3** 用户可以拖动窗口四边和四角来放大缩小，且不能小于最小尺寸。 — 成功标准:八个方向都能缩放，对边或对角保持不动；窗口不小于 800×520，也不超出视口；在最小尺寸下，竖栏、搜索栏、范围行、结果区和底部条都不重叠、不被裁掉，底部条中栏的进度轨仍可操作。
4. **CAP-4** 窗口的位置和大小在刷新后保留，且窗口始终在可见范围内。 — 成功标准:拖动或缩放结束后刷新页面，窗口回到相同的位置和大小；只点按没有移动时不写存档；首次使用时为 1000×680 且在视口居中；存档损坏时按首次使用处理；视口变小时窗口收回视口内，视口恢复后回到存档的位置，收回过程不改存档。
5. **CAP-5** 窗口打开时，用户可以照常使用窗口外的宿站聊天区。 — 成功标准:聊天区可见；窗口外可以看消息、点按钮、在聊天框打字和发送；窗口内的点击不会触发宿站的响应；焦点在宿站输入框时按 Esc 和 `/` 都不会被面板响应；Alt+S 仍可开关窗口。
6. **CAP-6** 窗口模式下面板的功能与全屏一致。 — 成功标准:所有模式、搜索、点播、内页、多选和设置都可用；来源菜单和顺序菜单出现在触发按钮旁，不被窗口裁掉，点窗口内外任意位置都会收起；底部条按窗口宽度收窄；选集和收藏随机面板、批量进度、播放进度浮窗、宿站选择框都能正常显示和操作；Esc 与宿站返回键仍是每次只关一层，最后关窗口。
7. **CAP-7** 放不下窗口的视口上，面板自动使用全屏。 — 成功标准:视口宽度 ≤768px 时始终全屏，手机布局不变，设置项灰显并说明「手机上始终全屏」；视口放不下最小尺寸时也全屏；这两种情况都不改选择和存档，视口变大后面板回到存档的窗口。

## Notes

- Decision: 2026-11-06 由 v6 迁入,状态 done,不重新打开。
- Assumption: 记住位置时一并记住大小（只明说了位置，但只记位置时每次都要重新缩放）。
- Assumption: 最小 800×520、默认 1000×680；真机验证时可微调，但要同步改本规格。
- Assumption: 位置和大小只存本机，沿用收藏随机面板的做法。
- Assumption: 宿站返回键在窗口模式下与全屏相同：先关面板内浮层，再关窗口。
- Assumption: 视口大于 768px 的触屏设备（如平板）可以用窗口模式。
