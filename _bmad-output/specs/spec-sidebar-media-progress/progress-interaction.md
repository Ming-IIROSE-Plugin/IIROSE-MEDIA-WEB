# 进度浮窗交互与验收

## 呈现与生命周期

- 初始关闭；点击侧栏「播放进度」后显示一个浮窗，重复点击聚焦已有窗口。关闭按钮只关闭浮窗；再次打开读取当前媒体，不复用陈旧快照。
- 浮窗独立于侧栏和插件主面板，在聊天界面中常驻。第一版不跨刷新保留开关和坐标。
- 视觉提案：约320px宽的紧凑圆角卡片、轻阴影、与宿站主题协调的实色背景；手机宽度不超过iframe可见宽度减24px。层级让浮窗可用，但不压住宿站必须响应的弹窗。
- 内容依次为可拖动标题区与关闭按钮、封面和媒体名、已播／总时长、可调整时间轴、−1m／−1s／+1s／+1m四个按钮。标题超长单行省略且可查看完整名称。
- 主操作与关闭按钮至少44px触控目标；拖动、聚焦、禁用与等待状态明确。进度条可通过键盘调整并具有可读名称和当前时间。
- 鼠标、触控均可从标题区拖动；进度条、关闭和步进按钮不触发窗口移动。位置约束使用iframe内可见坐标，处理宿站缩放、视口变化与手机旋转，保证窗口和关闭按钮可达。

## 进度与提交规则

真实播放时间与用户预览目标分别存储。拖动期间展示目标时间；松手后重新读取同一媒体的最新进度，再计算差值，避免把拖动期间正常播放的时间算进偏移。

1. 确认权限允许、房间与媒体身份未变、时间有效、时长已知且可定位；提交与实际发送前再次检查，denied/unknown不创建等待、不发送。
2. 将目标时间限制在0到总时长内；以秒计算 `delta = round(target - current)`。
3. delta为0时不发送；正数方向为 `>`，负数方向为 `<`。绝对差值为60的整数倍时使用分钟，否则使用整数秒；数量必须是正安全整数，不拆成多条指令。
4. 手势移动只更新预览；点击定位或拖动释放各提交一次，取消手势不发送。键盘操作同样在明确提交边界发送，不能因连续按键产生不可控重复提交。
5. 四个步进按钮按当前时间加减1秒或60秒；越过首尾时收敛到边界，以实际差值生成独立15控制报文。
6. 提交期间抑制重复操作，显示等待宿站更新；只有真实定位回读才能确认成功并显示真实值。有权且同步收到定位回调时立即恢复UI，不能被发送返回后的状态覆盖；5秒无回执解除等待并提示未确认，不自动补发，也不武断归因为权限失败。成功回读来源与容差的服务端有效性仍需实测。
7. 操作期间失权、换房、换媒体、失去有效时间或断连则取消旧预览与等待；旧操作不得发送，旧响应不得更新新状态。权限恢复清除旧拒绝提示，控制仍须满足媒体和连接等其余条件。所有路径保留聊天草稿及选区，不发送聊天，异常或失败也无聊天fallback。

| 提交瞬间当前时间 | 目标或操作 | 独立控制报文 |
| --- | --- | --- |
| 1:20 | 拖到2:00 | `!15[">","40s"]` |
| 2:00 | 拖到1:20 | `!15["<","40s"]` |
| 1:20 | +1s | `!15[">","1s"]` |
| 1:20 | −1s | `!15["<","1s"]` |
| 1:20 | +1m且剩余至少60s | `!15[">","1m"]` |
| 1:20 | −1m | `!15["<","1m"]` |
| 0:10 | −1m | `!15["<","10s"]` |
| 距结束20s | +1m | `!15[">","20s"]` |
| 0:00 | −1s | 不发送 |

拖动按差值使用15；16用于绝对位置但参数未知，本轮未实现，待参数证据与后续规格更新。任意整数秒／分钟的服务器支持仍待实测；若不支持，不得静默拆分、回退聊天或声称定位成功，需把验证结果带回规格调整。

## 状态处理

| 状态 | 呈现与行为 |
| --- | --- |
| 无媒体 | 显示暂无播放内容，禁用定位 |
| 直播、未知或无效时长 | 显示直播或时间未知，禁用进度调整，不猜测总时长 |
| denied：普通身份且无媒体管理角色 | 立即禁用滑块与四按钮，解释当前房间无媒体管理权限，零发送、零等待 |
| unknown：身份缺失/非法且无可确认全局角色 | 立即禁用，提示权限信息未就绪，零发送、零等待，不误报确定无权 |
| Info.room.identity数值1/2/3或window.rank[0]为1/5/3/6/7/a | 客户端权限预判允许，其余可定位与连接条件仍须成立，发送前再核验 |
| 本人点播且identity=0、rank='4' | 仍禁用；DOM #shareMediaUserName.title与window.myself比较只用于解释，不授予权限 |
| 权限恢复 | 清除旧拒绝提示，按最新媒体与连接状态恢复控件 |
| 预览/等待期间失权或window.roomnFull变化 | 立即取消旧预览与等待，旧操作不发送、旧回调不污染新状态 |
| 封面失败 | 显示自包含占位图，名称与时间仍可用 |
| 拖动中宿站自然推进 | 保留目标预览，提交时用最新真实时间计算 |
| 拖动中换曲 | 取消旧预览，更新新媒体，不发送旧指令 |
| 非媒体房间、断连或缺少 socket.send | 控制不可用，不尝试聊天路径 |
| 有权且真实定位回调即时到达 | 立即解除等待并恢复UI，不等超时，不被后续发送状态覆盖 |
| 宿站拒绝、发送抛错或5秒回读超时 | 保留真实值并显示失败或未确认；无自动重发或聊天fallback |
| 侧栏DOM暂缺 | 插件其他功能可用，等待适配节点，避免抛出异常 |

权限依据与字段层级详见 sidebar-integration.md；rank和roomnFull都在window顶层，禁止从Info.room读取。

## 验收场景

- CAP-1：桌面与手机检查标题精确更名、分组可折叠、旧电台不占位、当前媒体卡片原行为正常；重复适配及侧栏重建不产生重复入口。电台原在播放时不会留下不可见音频或破坏房间媒体音量。
- CAP-2／4：打开、重复打开、关闭再打开均只有一个窗口；关闭侧栏与主面板不关闭浮窗；鼠标与触控移动、滚动、旋转后仍可用，调整时间轴不会移动窗口。
- CAP-3：验证名称、封面、时间随当前房间媒体更新，包含相同标题的换曲或分P切换；测试破损图片、无媒体和未知时长。
- CAP-5：在允许控制的测试房间验证表中报文及实际媒体定位；拖动过程中零发送、释放最多一条控制报文；全程零聊天，草稿及选区不变，等待期间不重复发送。
- CAP-5权限：覆盖数值身份1/2/3与全局角色1/5/3/6/7/a、普通身份、本人点播不放行、缺失/非法字段unknown；denied/unknown按钮和滑块即时禁用、零发送零等待。覆盖权限恢复清提示、失权/换房取消预览等待、发送前复核与旧响应隔离。
- CAP-5边界：验证自然播放期间拖动、首尾限制、手势取消、换曲、网络断开、缺少send、发送抛错、权限拒绝及5秒未确认超时；有权同步回调立即恢复UI，覆盖权限/换房/回调交错。不能把本地预览、受控快照、发送日志或普通播放推进当作平台定位成功。
- 自动验证执行项目 npm run build 及相关测试；覆盖时间解析、差值/边界、拖动提交、换曲取消、权限矩阵与交错、正负秒/分钟、非法报文和零聊天调用。可注入发送器验证状态机，但默认发送器与组件必须验证实际独立协议。本轮仅更新文档，沿用调用方既有验证记录，不重新构建。
- 真实站点依项目验证流程刷新后只注入一次；实际控制限已获授权测试环境，不在普通公共房间反复发送试验媒体。
