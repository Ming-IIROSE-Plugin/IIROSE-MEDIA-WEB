- (decision) 基线（A12 先取）：dist/bundle.js 438.69kB / gzip 132.49kB，70 文件 / 1258 用例全绿；本轮不设体积阈值（维护者已取消守门）
- (note) 扫描结论：page 直连 Api 仅 1 处（mainAppCategories 拼多源 baseUrl），分层方向健康；四个缺口是存储直连、分页包装重复、平台无接口、错误提示重复
- (note) 存储：生产代码直连 localStorage 约 50 处（BiliBiliSettings 16、PluginSettings 9、LocalStorageUtils 8、SetBiliBili 8、NetEaseSettings 7、CommonSettings 6 等），LocalStorageUtils 只服务配置初始化
- (note) 分页：7 个 Service（AllVideo/Bilibili/Favorites/InnerPage/NetEase/Radio/Recent）各自重复 mediaData Promise 包装；splitByPage 在 bilibili/shared 与 netease/searchResults 各一份
- (note) 错误提示：18 处 ShowMessage.show((error as Error).message)，集中在 platforms 的 search/pages/collection/playback
- (capability) CAP-1 存储访问收敛到单一入口：生产代码不再在各模块里直接拼 key、JSON 编解码与 try/catch，已有 key 与数据格式保持不变
- (capability) CAP-2 分页加载器单一实现：7 个 Service 复用它，两份 splitByPage 合并为一份
- (capability) CAP-3 平台检索接口类型化：四个平台实现同一 interface，新平台按类型约束补齐，不引入运行时分支
- (capability) CAP-4 错误提示收敛：失败分类 + 单一上报入口，四处以上重复的 ShowMessage 调用消失
- (constraint) 行为、文案、UI、宿站交互不变；现有测试不得放宽；不重写平台实现与网络层
- (constraint) 存储 key 与已存数据格式不变，升级后老用户数据可直接读取
- (event) spec 创建完成
- (decision) stories：1 存储收敛、2 分页加载器、3 平台接口类型化、4 错误提示收敛；均不设 checkpoint，按序执行
- (event) Self-Validate Pass 1 通过：四条 capability 各有可测 success，constraints 明确不改 key/不重写实现/不放宽测试，non-goals 排除了基类抽象与 Service 泛型化
- (event) Self-Validate Pass 2 通过：扫描数据（50 处存储、7 处分页、18 处提示、四平台方法）全部落入 SPEC 或 story；错误分类粒度写成 open question 交给 story 4
- (note) story 3 侦察：四家平台没有共同方法（NetEase.searchFor*BasicsData、Bilibili.searchFor*/getRecommend、Radio.searchSongs、AllVideos.searchAllVideos），且 Platform 接口已存在但只描述 UI 形状；强套统一 search 接口只能靠适配对象，会产出无人消费的死代码
- (decision) CAP-3 调整为「平台检索描述表」：把 mainAppCategories 里各范围的 searchAction 闭包提取为集中数据（平台 id / 标签 / 范围 + 取数函数），UI 分类表由它生成；新增平台只加数据，不改 UI 表
