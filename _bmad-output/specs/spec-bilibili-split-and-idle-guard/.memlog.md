- (decision) 按 A12 先取基线：dist/bundle.js 437.25kB，vite 报表 gzip 131.99kB，gzip -9 实测 131,215B，69 文件/1253 用例全绿
- (note) BilibiliPlatform 782 行、12 个方法与 2 个工具函数：推荐 45、视频搜索 72、直播搜索 41、分 P 104、详情 27、播放 68、VOD 140、选集 73、prepareAndSendMedia 36、LOD 59、dash 64、stream 14
- (note) PlaybackMode 已有 subscribe(listener)+toggle(kind)+state，可按点亮状态驱动 Loop/Shuffle 的媒体桥订阅；风险是点亮前没有连续快照历史，结束前重播的判定窗口可能变短
- (decision) 本轮三块：BilibiliPlatform 拆分（≤400 行/文件）、按需订阅（未点亮且浮窗关闭时零轮询）、体积守门（构建后脚本 + CI 步骤）
- (capability) CAP-1 BilibiliPlatform 拆成多模块，每个文件 ≤400 行，公开静态方法签名与调用点不变
- (capability) CAP-2 循环与随机未点亮、浮窗未打开时，媒体桥不轮询；点亮或浮窗打开后行为与现在一致
- (capability) CAP-3 构建产物体积被自动校验：超过 450kB 或 gzip 134kB 时 npm run build 或 CI 失败并给出实测值
- (constraint) 单文件 UMD；行为、UI、文案、宿站交互不变；现有测试不得放宽；守门脚本只用 node 内置模块
- (event) spec 创建完成
- (decision) stories：1 拆 BilibiliPlatform、2 按需订阅、3 体积守门；均不设 checkpoint，按序执行
- (event) Self-Validate Pass 1 通过：三条 capability 各有可测 success，constraints 排除了改轮询间隔与新增依赖，non-goals 明确
- (event) Self-Validate Pass 2 通过：基线数字、方法区间、PlaybackMode 能力、CI 现状全部落入 SPEC 或 story；点亮前无快照的风险写成 open question 交给 story 2 实测
- (note) story 2 首版实现（零轮询+被动订阅+事件取样）经审查证伪：宿站没有媒体事件，停表会让别人点歌/切歌/播放结束/换房/断线都不被发现，且同一监听器双注册会在面板关闭时被误删、polling 计数不对称导致定时器泄漏
- (decision) CAP-2 降级为空闲 1s / 活跃 250ms：用 activeTags 引用计数驱动 HostMediaBridge.retune；面板、浮窗、已点亮模式各自标一个 tag；事件驱动处（自we发报文、侧栏媒体卡变化）用 poke 立即刷新
- (note) 测试契约更新一处：HostMediaBridge.test.ts 的周期性 installHooks 用例由 advance 250ms 改为 1000ms（空闲节奏变更），并新增 polling.test.ts 5 条覆盖节奏切换与 poke
- (event) story 2 重做完成，测试 70 文件 / 1258 用例全绿
