- (decision) 基线实测：bundle.js 475.0kB（gzip 142.8kB），内联 CSS 69.4kB（gzip 11.8kB），204 个模块
- (decision) 本轮范围取 P0+P1：依赖替换、无用依赖清理、CSS 扫描面收敛、启动轮询与 setEnv 时序；巨型文件拆分列为非目标
- (decision) 删除 src/main.ts 中向 head 注入 unpkg react-scan 的代码：项目用 Preact，该脚本无用且引入外部执行风险与额外网络请求
- (decision) 用 uqr 替换 qrcode（含 dijkstrajs/crypt/charenc/is-buffer 依赖链，95kB 原始/29kB gzip，仅服务 B 站登录二维码一个 toDataURL 调用）
- (decision) Tailwind 用 @source 把扫描面锁定到 src/，排除 _bmad-output/specs 等 Markdown 中被误生成的 8.5kB（12.6%）类
- (decision) md5 换成本仓内轻量实现，去掉 md5/charenc/is-buffer 依赖链（8kB 原始），仅用于 B 站 WBI 签名
- (decision) 移除 package.json 中零引用的 jquery、canvas、html-entities
- (decision) HostMediaBridge 的 250ms 轮询降频/改为事件驱动，页面加载后在面板未打开时不持续轮询
- (decision) Environment.setEnv 改为可等待的就绪态，API 层首次请求前等待代理地址确定；ipinfo 探测结果按天缓存
- (decision) 开启 TypeScript noUnusedLocals/noUnusedParameters 并清理现有 14 处生产代码告警
- (decision) vite.config.ts 的 lib 入口由 src/main.js 改为 src/main.ts
- (constraint) 产物必须是单文件 UMD：油猴 @require 与 iframe 注入方式决定不能 code-split 或产生额外 chunk
- (constraint) 除替换 qrcode 的 uqr 外不新增运行时依赖；新依赖必须支持 UMD/IIFE 单文件打包且体积可控
- (constraint) npm test 与 npm run build 必须全绿；UI 行为与宿站交互契约不得改变
- (constraint) 格式化重排必须单独提交（style: 前缀），不得与功能 diff 混提
- (capability) CAP-1 产物体积：bundle.js ≤ 390kB 且 gzip ≤ 120kB，同时 B 站扫码登录仍可用
- (capability) CAP-2 启动开销：加载后不再注入任何外部脚本，面板未打开时不产生高于 1Hz 的轮询
- (capability) CAP-3 依赖与静态检查：package.json 无未使用依赖，noUnusedLocals 开启且构建无告警
- (assumption) uqr 生成的二维码可转为 img 可用的 data URL 并在宿站弹窗内展示，视觉与现有一致
- (assumption) ipinfo 国家判定可按天缓存，缓存命中时跳过网络探测不影响代理选择正确性
- (note) 巨型文件（MainAppContainer 1292 行 / NetEasePlatform 1271 行 / ShufflePicker 1068 行 / BiliBiliVideoAPI 1050 行）确认为可维护性问题，但不在本 spec 范围
- (decision) story 1：删除 react-scan 注入（CAP-2），独立可审，不动 APP.toString 注入逻辑
- (decision) story 2：qrcode 换 uqr（CAP-1），保持 generateQRCodeBase64 的 Promise<string> 契约
- (decision) story 3：Tailwind @source 收敛到 src（CAP-1），不改 important 配置
- (decision) story 4：md5 本仓实现 + 移除零引用依赖 + vite 入口改 main.ts + 开启 noUnusedLocals（CAP-3）
- (decision) story 5：环境就绪可等待 + ipinfo 按天缓存 + HostMediaBridge 无人订阅时停表（CAP-2）；订阅期间不降频以免进度条变卡
- (decision) 5 个 story 均不设 spec_checkpoint / done_checkpoint，按列表顺序连续执行
- (note) 未纳入本轮：Api/index.ts 的四种传输混装与重复代理常量、Api 目录结构、渲染层 memo 优化——均非 load-bearing，留待后续 spec
- (event) Self-Validate Pass 1 一致性与 lean 通过：3 条 capability 均有 intent 与可测 success，constraints 实际改变设计（单文件 UMD 直接排除 code-split 方案），non-goals 明确，CAP 编号唯一，无装饰性 prose
- (event) Self-Validate Pass 2 保留性通过：审查结论中的 react-scan、qrcode、CSS 扫描面、md5、零引用依赖、轮询、setEnv 时序、noUnusedLocals、vite 入口 9 条 load-bearing 主张全部落到 SPEC 或 story；巨型文件与网络层重写落为 non-goal；代理常量重复记为未纳入 note

- (decision) open question 1 已解决：删除 react-scan 后不保留任何调试开关，story 1 按原样执行
- (decision) open question 2 已解决：保留 tailwind.config.js 的 important: true，不改配置——宿站全局样式可能覆盖插件，稳定优先于 CSS 体积
- (direction) 维护者授权实测 global important 的影响，结论仅作记录，不改变保留配置的决定
- (event) SPEC 更新：Open Questions 清空，CAP 与 stories 不变
- (note) important 实测（2026-11-02，真机 iirose.com，1400x900，登录态注入两份 bundle）：important:false 产物 466,288B vs 基线 475,044B；面板默认页 395 个元素 x 14 项 computed style 全部一致，差异 0

- (note) story 2 实测：qrcode→uqr 后 bundle 474.89→460.73kB（-14.16kB），gzip 142.71→136.98kB（-5.73kB）；此前 95kB/29kB 的估算是错误量纲——visualizer 的 renderedLength 是未压缩源码长度，与 minified+gzip 收益不可直接换算
- (decision) CAP-1 success 修正为 bundle ≤ 450kB 且 gzip ≤ 134kB：以实测基线为准，给 story 3（CSS 扫描）与 story 4（md5）留出约 10kB/4kB 余量；390kB 的原目标不现实

- (decision) 二维码参数对齐旧 qrcode 默认值：ecc=M、静区 4 模块（ISO 要求）、pixelSize=4（旧 scale=4 同量级）；实测输出 212x212，jsQR 解码内容逐字符一致
- (decision) 把 SVG data URL 生成提取为 src/Account/BiliBili/qrCode.ts 的纯函数并加 3 个单测（尺寸/静区/矩阵差异），private 方法保持原契约
- (decision) 修复 npm 依赖变动引发的构建回归：显式声明 @types/node，tsconfig lib 由 ES2020 升到 ES2022（代码已用 Array.prototype.at，target 仍为 ES2020）
