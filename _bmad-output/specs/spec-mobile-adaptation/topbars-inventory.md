## 维护者点名的热点

UX 评审必须先覆盖这几处，它们是维护者主动指出的不顺手点，不是推导出来的：

- ① 的四个分类切换入口（音乐／视频／设置／关于）在小屏连点顺不顺。
- ② 的**搜索**与**下一页**——两个被单独点名的控件。
- ③ 与 ④ 整体"用起来不顺手"（维护者原话），需要评审给出具体成因，而不是只修溢出。

## 共用事实

- **断点混用**：全插件只有 `max-[490px]`（视口宽度）与 `max-[780px]` 两个断点，无更细的分档，也无基于容器宽度的判定。
- **容器宽度**：`.IIROSE_MEDIA_CONTAINER` 为 `position:fixed; width:100%`，其宽度等于宿站 iframe 的宽度。宿站若给手机浏览器一个偏宽的布局视口，全部视口媒体查询都会按"桌面"生效，而用户看到的是窄屏——②的 P0 症状与此一致，故 ② 的根因未定，不可直接写死断点。
- **图标**：一律自包含，注册在 `src/app.css`（元素 id 或类名 + `::before` content + `font-family:"md"`）；不得借用宿站 `mdi-*` 类。
- **既有证据**：仓库根目录 `ux-01-initial.png`（1280 桌面）、`ux-02`/`ux-06`（400px 移动，列表视图）；无 360/390/430 档与横屏档证据，待 UX 评审补齐。
- **相邻约束**：任何栏内新布局都必须保持 `grid-auto-rows:max-content` 等效的自适应高度，否则动作按钮会被 `overflow:hidden` 裁切（项目已记载的坑）。
