# 点播归属与生命周期（ownership-and-lifecycle）

## 本人点播判定

宿站把当前媒体点播者写在 `#shareMediaUserName` 的 `title` 属性上，本人昵称在 `window.myself`。

- 判定成立：两者都非空，且去除首尾空白后严格相等。
- 判定不成立：任一为空、剪掉空白后不相等、`window.myself` 不是字符串。
- 判定只在动作前一刻取值，不缓存，不复用 `HostMediaBridge` 的 `controlMode`（后者含权限与播放状态，语义不同）。
- 昵称的 HTML 实体/全角差异不做归一化；不一致即视为「非本人」，宁可不动。

## 两条开关的归属语义

| 场景 | 单曲循环 | 收藏随机 |
| --- | --- | --- |
| 当前曲目本人点播 | 正常触发 | 正常触发 |
| 当前曲目他人点播 | 不动作，保持点亮待命 | 不动作，保持点亮待命 |
| 点播者信息未知 | 不动作（保守） | 不动作（保守） |
| 本人点播被他人中途接管 | 不打断；下次本人曲目恢复 | 同左 |
| 本人重新点播任意曲目 | 立即纳入判定 | 立即纳入判定 |

- 「待命」在界面上仍是点亮态，不主动弹提示（否则每次别人点歌都刷屏）；用户点按点亮的待命按钮时，**首次点按只弹出待命原因、不切换**，再点才熄灭（触屏无 hover、键盘 Enter 同一路径）；每次重新进入待命重置为「未说明」。`title` 与读屏状态区仍保留。

## 单实例

- 页面级单例键（挂 `window`）标记自动播放控制器，后注入的实例不启动判定，避免重复注入产生两次发送。
- 同页多标签页无法互相感知，不做跨标签协调（见 SPEC Non-goals）。

## 停止条件（任一成立即停止并熄灭）

- 换房：房间标识（`roomnFull`）变化。
- 断线：`socket.readyState` 非 1；恢复后不自动重新点亮。
- 媒体消失：无当前媒体、时长为 0 或未知。
- 插件卸载 / 侧栏容器被移除后无法重建。
- 用户关闭开关或点亮另一个开关（互斥）。
- 连续失败达到上限（循环 1 次失败即停；随机 5 次换曲失败即停）。

## 刷新与持久化

- 开关状态只存内存，刷新、重进房间默认熄灭。
- 唯一的持久化项是随机选择与权重（按账号与平台存本机 `localStorage`，见 shuffle-mechanics.md「选择的存储」）；原设置「专辑/歌单参与随机」已退役。开关点亮状态不持久化。

## 与其他模块的边界

- 不改写 `HostMediaBridge` 的权限判定与控制白名单；只新增「本人点播」的只读判定与快照字段。
- 不改动「播放进度」浮窗的交互与发送路径。
- 不接管宿站原生播放/暂停/换曲按钮的行为。
- 自动动作与用户手动操作并发时以用户为准：手动点播、手动定位后 2 秒内不自动触发。
